# notebook-plan-contract.md — where review state lives

The notebook is the shared memory between phases, children, and handoff contexts. The coordinator owns writes; children return compact records and never race pages. Stage documents are loaded per `kernel/references/context-loading.md` (boot set + stage map + read-once rule); pages and handoffs carry refs, not document bodies.

## Page layout

A re-pull starts the next review state and writes **distinct** frame + contract pages for it — never overwrite an earlier state's pages in place (the new frame reuses `subject_path` with the new `subject_oid`; the tree itself is updated in place).

### Immutable seal and composition

The original sealed `pipeline-frame-…` body retained unchanged includes the literal verifier-child contract and immutable approved plan. Put P0 reality/pins, vector `fleet_plan`s, basis and phase metrics in coordinator-owned bounded stage-record pages. A small state-head page lists ordered stage refs/hashes and sequence. The logical frame = sealed plan + this explicit composition; each handoff loads only active records. Do not use a hash-only replacement: never overwrite the seal with hash-only text. `frame_sha` stays the approved-plan SHA, never an engine commit, mirror `frame.json`, or mutable composition.

The guarantee is that every former frame field stays reachable and authoritative through the seal plus its referenced stage-record pages and state-head index: subject/base identity and changed files; contract/source pins and designation; research binding/fallback; chunker/verifier identities; claims/units/join refs; every fleet plan/amendment; P0 input budget, sweep, hard cases and source-consistency; `repair_required`, `review_basis`, and phase/checkpoint metrics. Tests must prove this reachability. A handoff loads only the active records; it does not rebuild the subject or a semantic verdict.

Reference pages by name. Children `notebook_read` on demand; they do not preload bodies. The coordinator serializes writes with a process-local ordering so same-name writes don't race.

### State-bound artifact store

The run retains exact source captures and capture provenance, `claims-draft/3`, the units manifest and unit payloads, P0.4 per-box JSONL attempts, the merged `join-draft/1`, P0.5 check/assignment evidence and the run manifest. Record exact-byte sha256 refs; keep the shipped chunker path/hash/recipe and the pinned verifier path/hash/tool_version bound to `cure_light_source_head_oid`. Keep the p0-pack receipt plus the produced claims-list/assignment/instruction refs/hashes, and the run-envelope projection ref/hash (`run-manifest.json`, `run-verification/1`) and the current fast-child `verify join` verdict ref/hash/exit code bound to the exact input refs/hashes (optional `verify claims`/`verify units` diagnostic verdicts use the same shape when run and never gate); gate evidence stores the exact child verdict bytes/code for those inputs. These identities make artifacts verifiable, not semantically canonical — a verdict proves recorded mechanics, never semantic proof. p0-pack owns claims-list, assignment and instruction production; P0.4 children write only their assigned box file, and the coordinator owns notebook pages and the merge. Heavy join rows stay in the artifact store and are consumed by path, not pasted wholesale into the coordinator's context. Coordinator merge ownership is complete consumption: the coordinator must consume all required claim/unit/closure/trace records in bounded artifact slices before asserting completion, never trusting receipt counts or cherry-picking findings. Two stores are allowed, and either (or a documented mix) may be used:

- **paginated content-addressed notebook artifact pages** (the `claims-`/`coverage-` pages plus bounded `-p<k>`/artifact shards), or
- a **durable run-artifact store** mounted outside the subject (surviving sandbox teardown), with the notebook page carrying refs + hashes and the reassembly rule.

Whichever store holds the recorded bytes — notebook artifact pages or a durable run store — it is content-addressed and verifiable: run-store files used only as execution cache are not authoritative; notebook pages may hold the recorded bytes directly (paginated, content-addressed) under the same reassembly/hash-equality rule, and when the durable store holds the recorded artifact the notebook pages are projections of it. **No pretty-JSON substitute:** a re-rendered summary, a pretty-printed copy or a partial excerpt never replaces the recorded bytes, and a projection whose reassembled bytes/hash differ from the recorded artifact is invalid. **Lifecycle:** recorded artifacts and their projections are kept through the state's closure/finalization window and retired only after a durable snapshot with matching hash lands (claims/coverage pages per their table rows); a retirement never leaves a live state page referencing unreachable bytes. A new review state gets a new `-s<n>` set and never overwrites or reuses the previous state's artifacts.

A per-box artifact has one child writer and an exact assigned path; preserve failed attempts and require P0.5 checks before publishing a current merge. A child success message is not proof that the expected file exists. Missing or truncated rows never become zero-link candidates. This file-based output decision applies to P0.4; it does not relocate V1's authoritative coverage records out of the notebook.

### Coverage pages

`coverage-<owner>-<pr>-s<n>` is the summary/index for a state's Vector 1
changed-unit accounting; `coverage-<owner>-<pr>-s<n>-p<k>` are its ledger
shards, paged by surface/shard/claim group so a mega-diff ledger stays inside
a notebook page (50 KB / 2000 lines). The index carries the denominator,
counts, exclusion policy and completion flags plus exact shard refs, so
closure and finalization can cite the accounting without loading every shard.

### Byte caps and single emission

Count UTF-8 bytes, not characters. An ordinary ledger row ≤384 UTF-8 bytes; a ledger shard ≤16 KiB / 500 lines; a summary/index ≤12 KiB; combined V1 coverage + claims projection ≤80 KiB. The operator may approve a named larger allocation. The platform 50 KiB/2000-line limit stays an independent hard bound. Never truncate on overflow: overflow splits or HOLDs, never truncates proof fields, never drops a unit; pending never becomes excluded.

Each page header binds complete identity/manifest/assignment/frozen-directory hashes. Use a deterministic evidence-ref dictionary instead of repeated prose. Long anchors/edges use linked continuation records or new shards. Full reports remain accessible through closure/finalization.

Generate/freeze once; collect diagnostics as counts/refs, with no helper printing, no patch-with-echo, no re-cat of an unchanged body, no pretty-print/re-serialize of an authoritative artifact, and no printing a whole multi-page bundle. On the by-value interface, one page-body read + one exact write remains unavoidable: call it two transits, not zero-copy. Necessary seal/readback remains. A genuine correction makes a named new version.

Coordinator-owned bounded trail shards in `pr-<n>-review` cover V2/V3 review-check/lens/research trails and confirmation attempts: refs/counts, current finding rows, and gate-visible pending/refuted/disputed limits. Do not re-paste every historical attempt or full rendered draft. Required final draft/confirmation bytes stay pinned in the artifact store; every text-stage child still receives the full target draft via its pinned input.

## Content rules

- **Findings are recoverable facts** — keep the evidence-format rows; discard tender re-derivable code trivia freely at handoff.
- **The symbol map is a bounded state cache.** Structured artifact data (symbols, counts, capped locations) that survives the state's handoffs because V3 and the post-handoff yagni pass consume it — never raw search logs. A re-pull is a new state: a new `-s<n>` page, never an overwrite or silent reuse.
- **Coverage records are structured machine records, not findings.** Vector 1's changed-unit accounting (unit/range, accounting state, attribution edges, evidence refs — conformance-pass.md) lives in the `coverage-<owner>-<pr>-s<n>` summary/index and its bounded `-p<k>` shards; these in-notebook pages are the authoritative store — never findings rows, raw logs, or scratch files. Workers read only their assigned pages/slices. A re-pull is a new state with its own `-s<n>` coverage pages, never an overwrite. The summary page carries the denominator + counts + completion flags + per-shard assignment refs/digests so closure/finalization can cite the accounting without the shards; coverage pages stay through the closure/finalization window and retire after durable snapshots land — a closure run never depends on a dead link.
- **V1 validates/freezes the claim universe.** `claims-<owner>-<pr>-s<n>` references the retained Phase-0 draft and the source-bound V1 validation/freeze record. A draft summary or a child's local slice is never the complete queryable directory. Preserve source identity, claim interpretation and changes from the draft; the detailed freeze schema remains an operator checkpoint. Negative attribution without an adequately validated/queryable universe returns `UNRESOLVED`, never permission inferred from P0.5.
- **Sources enter the contract only by explicit designation.** In-diff spec/design material is a claim source only when the PR body, linked issue or a locked decision points at it; repo convention interprets a designated package (normative vs advisory, delta vs baseline), never authorizes one (intake-and-scope.md §0.2). Non-capturable pointed material is context with a stated limitation. Source/consistency/`review_basis` records are coordinator process records, not findings.
- **Contract repair is a new state, not an overwrite.** A changed PR body/issue or in-diff source — even with an unchanged subject OID when no code changed — writes a new `-s<n>` contract/claims set; prior states stay addressable at their own pins (closure-verification.md).
- **Decisions are non-recoverable** — always persist: operator deferrals, closed-by-operator records, locked decisions from the issue. Never let them go stale or vanish on compaction.
- **The contract page is verbatim, bounded.** The Phase-0 contract is the one long-form page: PR claims + locked decisions preserved byte-exact (intake-and-scope.md §0.2). Never paste raw diffs, logs, or kernel text into it.
- **The contract is written once per review state, then referenced.** Capture the literal contracted text once into the state's authoritative page at seal/Phase 0; later frames, gates and spawns reference it with pins/counts — no prose restatement in every spawn or notebook update. The literal rendered verifier-child contract stays present once in the sealed frame and is never replaced with a hash-only reference. A distinct new state still writes its own distinct verbatim contract; retention, readback, queryability and durability are unchanged.
- **Derived reads are bounded.** Consume derived artifacts by refs plus bounded selections — never a full claims/join/symbol-map dump; exact source evidence access for judgment is unchanged.
- **No raw transcripts/logs.** A vector's dead ends and working notes do not belong in the notebook; the closure table's `re-opened` row records the reason concisely.
- **Research compliance is part of the record.** Per-split Vector-2/3 RESEARCH TRACE outcomes (compliance table) append to `pr-<n>-review` with the vector; shadow-split comparisons land there too when enabled; confirmation-run verdicts, adjudication outcomes and their confirmation research traces append there too when the pilot is on — coordinator-only trail and artifacts, children never write the notebook.

## The seal-then-handoff step

When `handoff` is available and the operator confirms the frame:

1. Write and read back — verifying both match — `pipeline-frame-<owner>-<pr>-s<n>` (compiled options + planned subject mechanism — the manifest's tree fields land at the Phase 0 gate) and `pr-<n>-review` (findings skeleton); the readback is the notebook write-availability proof (requirements-check.md row 6). The seal freezes the verifier pin, the literal delegated execution contract, and the fleet policy (per-vector groups, the at-most-two-per-child cap, depth-budget units); each vector's `fleet_plan` lands in its immutable stage record at its compile gate (intake-and-scope.md §0.3b), and the state head adds that record. The readback is the proof of text freeze — the tool's JSON alone cannot prove delegation happened.
2. Discard recoverable code-trivia pages; refresh the durable decision page.
3. Draft the handoff prompt that carries ONLY: the frame's location, the current state (intake complete, requirements pass/fallback), the immediate next step (Phase 0 pull subject + contract → Vector 1), and any blocker or failed path worth avoiding.
4. Call `handoff` with `discardPages` for code-trivia pages and the task prompt pointing at the sealed frame and state-head pages by name.

The next context reads the sealed frame plus only its active state-head records, loads kernel references on demand, and kicks off Phase 0 → Vector 1 — it does not re-fetch the kernel.

## If no handoff

Continue in-session; the frame and findings pages still carry the state. The operator sees the compiled plan inline instead of via a fresh context.

## Gate decisions (strict receipts, opt-in)

Interactive mode keeps the existing explicit shown-frame confirmation. Where the host provides them, strict gate receipts are opt-in; they are never required for interactive engine users. After an approved frame write/readback, pin the exact immutable approved-plan bytes: `frame_sha` means that approved-plan SHA — never the engine commit or a mirror `frame.json` SHA. Later gate answers are `{decision, frame_sha, decision_ref}`; `decision_ref` resolves to a trusted host-side immutable decision record binding run/job, review_state, gate name + ordinal, the current gate-evidence snapshot refs/hashes, the policy hash, and the decision/rationale/operator authority. Hash the exact retained bytes; no normalized or reserialized hash ambiguity. The driver verifies job/gate/state/plan/policy and fresh evidence before sending a receipt; a missing, malformed, stale, replayed or wrong-gate receipt, or an unreadable ref, is HOLD/error, never the generic auto-approval fallback. The container cannot approve itself; host gate-store isolation is preserved. An operator substantive change writes a new decision artifact and triggers the existing recompile/new-state rules — never squeezed into a misleading accept token. Unknown closure gates need an explicit decision; no default accept.
